# 学习通「自动播放下一节」使用指南

- 脚本：[`src/xuexitong-auto-next.user.js`](../../src/xuexitong-auto-next.user.js)（`@version 1.8.0`，版本号读法与发布纪律见 [`docs/adr/0012`](../adr/0012-release-branch-and-version-scheme.md)）
- 目标站点：`mooc1.xuexitong.com` 的**学习页面**（`.scratch/xuexitong-auto-next/spec.md` 是本脚本的完整决策依据）
- 当前行为口径：**第八轮**——推进不再是「点一次下一节、走一个节点」，而是**从章节树直接跳到当前节点之后第一个未完成节点**（只向前），见 [`docs/adr/0010`](../adr/0010-jump-to-next-unfinished-node.md)；而且**平台判定「完成」不等于媒体播完**，脚本会把手上这条播完再推进，见 [`docs/adr/0011`](../adr/0011-completion-is-not-ended.md)。再往前一档的两段续播阶梯见 [`docs/adr/0009`](../adr/0009-auto-resume-ladder.md)
- 还没装过？先看仓库根目录的 [`README.md`](../../README.md)（装篡改猴 + 装脚本的新手版，面向不懂代码的使用者）

## 一、安装

前置：浏览器装好 **Tampermonkey**（Chrome / Edge 均可，本脚本按 Chromium 内核的行为实现）。

**装篡改猴、装脚本的完整三步在仓库根目录的 [`README.md`](../../README.md)** —— 那是唯一的新手路径，面向不懂代码的使用者，本文不再重复。本节只留两件与这个脚本有关的事：确认版本、更新。

### 装好了怎么确认版本

在目标学习页的控制台执行：

```js
window.__xuexitongAutoNext.VERSION   // 期望 "1.8.0"
```

返回一个像 `"1.8.0"` 的号 = 脚本在这页跑起来了，这就是篡改猴面板里那个 `@version`；返回 `undefined` = 装的是旧版，或脚本压根没在这页跑起来（先看 `@match`，见第二节）。

号怎么读：**`1.<轮次>.<补丁>`** —— 中间那位是**行为口径的轮次**（`1.8.0` = 第八轮）。所以看到号就知道轮次，也就知道有没有你要的那个修复。

只想确认「某个特定能力在不在」，改用**功能标记** —— 脚本里那处能分辨轮次的存在性印记，例如：

```js
typeof (window.__xuexitongAutoNext || {}).CONSTANTS.TREE_RECHECK_GRACE_MS   // 期望 "number"（第八轮起才有的常量）
```

⚠️ 功能标记与版本号分工不同：**功能标记只回答「至少是第几轮」，不回答「是不是最新」**——那个问题只有版本号答得了（见 [`docs/adr/0013`](../adr/0013-version-marker-instead-of-grant.md)）。

### 更新脚本

**正常情况下不用管**：脚本配了自动更新（`@updateURL` 指向发布分支 `main` 上的这份文件），篡改猴会自己定期检查、拿到新版自动装上。

想立刻拉一次：篡改猴的「管理面板」→ **「检查脚本更新」**（不同版本位置略有差别，一般在「实用工具」那一带）。

⚠️ **发布发生在 `main` 分支上**（日常开发在 `develop`）：维护者若刚修好、还没合入 `main`，你这里自然拿不到 —— 那不是更新坏了，见 [`docs/adr/0012`](../adr/0012-release-branch-and-version-scheme.md)。

> 给 agent / 自动化：完整流程（含硬边界）见 [`docs/agents/userscript-install-via-playwright.md`](../agents/userscript-install-via-playwright.md)。那条路上唯一的坑：`playwright-cli` 打开 `.user.js` 的 URL 后**只 `reload` 不会弹安装页**（页面停在裸 JS 文本上），要 **`goto` 同一个 URL** 才会唤起安装页（并另开一个 `chrome-extension://…/ask.html` 标签页）——`tab-select 1` → 点「重新安装」，装完两个标签页都会关掉。

## 二、配置

脚本**没有设置界面**（`@grant none`，不用 `GM_setValue`），配置就是改脚本本身。一共三层，**只有第二层是日常会动的**：

### 1. 作用域配置 —— 只在站点改版时动

| 位置 | 现在写的 | 作用 |
|---|---|---|
| 元数据块 `@match` | `https://mooc1.xuexitong.com/mycourse/*` | 决定 Tampermonkey 在哪些 URL 注入脚本 |
| `adapter.isStudyPage()` | hostname 尾部 `mooc1.xuexitong.com` + 路径 `/mycourse/(studentstudy\|studentstudycourse)` | 决定注入之后真的开跑（防止在课程列表页也跑起来）|

⚠️ 两处是**双保险**，改其一必须同步改另一处；`@match` 放宽了但 `isStudyPage` 不放宽，脚本会静默不启动（状态条也不出现）。

### 2. 行为配置 —— 唯一调参处（脚本头部 `const C = { … }`）

所有时限、次数、节奏都在这一个对象里，状态条文案里的数字也是由它们拼出来的（改常量，文案自动跟着变，不会出现「文案说 20 秒、代码等 30 秒」）。

| 常量 | 默认 | 含义 | 什么时候动 |
|---|---|---|---|
| `TICK_MS` | `1000` | 采样间隔 | 基本不动 |
| `ADVANCE_DELAY_MS` | `15000` | 一个可播任务点**播完后**固定等这么久再去找下一个 | 嫌翻节慢可调小（如 `5000`）；它是 spec 共识第 3 条写死的固定延迟，改它属行为变化，改完务必看一轮真机 |
| `RESUME_INTERVAL_MS` | `5000` | 续播阶梯每两次尝试之间的间隔 | 网络慢可拉大到 `8000`；它同时接走了原来的「暂停宽限」 |
| `RESUME_MAX_ATTEMPTS` | `5` | 续播阶梯**第一段**次数 | 想让脚本更执着/更早放弃就调它 |
| `RESTART_MAX_ATTEMPTS` | `3` | 重启脚本后**第二段**次数 | 同上 |
| `STALL_TIMEOUT_MS` | `20000` | 播放中 `currentTime` 这么久不前进即判「卡住」→ 直接停 | **`stalled` 唯一的救法就是拉长它**（不要把它塞进续播阶梯，理由见 `0009` 的 Considered Options）|
| `UNREADY_TIMEOUT_MS` | `30000` | 等页面交出可播元素的上限，等不到 → `mediaNotFound` 停下 | 同上，`mediaNotFound` 也靠拉长时限处理 |
| `EMPTY_CARD_GRACE_MS` | `3000` | 一张卡片一个任务点都没有时，先按这么久当「还没渲染出来」 | 一般不动 |
| `TREE_READY_GRACE_MS` | `10000` | 章节树还没铺好时先等这么久，仍拿不到才回退到「点下一节」 | 一般不动 |
| `TREE_RECHECK_GRACE_MS` | `15000` | 树说本节点还有未完成、脚本却一个未完成的都没看到时，先按这么久复查（第八轮新增） | **别调到 6 秒以下**：平台刷新章节树的往返实测 3–6 秒，调小了这条修复就失效 |
| `ACTION_COOLDOWN_MS` | `4000` | 同类动作（定位、续播等）的最小重复间隔 | 一般不动 |
| `ADVANCE_REPEAT_GUARD_MS` | `8000` | 点了「下一节」页面却没变化时，多久内不再重复点 | 一般不动 |
| `TASK_POINT_CACHE_MS` | `3000` | 任务点元素的重扫间隔 | 一般不动 |

三条纪律：

- **改完必须重新安装脚本**（覆盖），页面里跑着的还是旧代码；
- **改了行为就要递增版本号**：元数据块的 `@version` 与脚本内的 `SCRIPT_VERSION` **两处一起改**（`1.<轮次>.<补丁>`，见 [`docs/adr/0012`](../adr/0012-release-branch-and-version-scheme.md)），改完跑下面这条确认两处一致：

  ```bash
  node src/tests/version.test.js
  ```

- **用例跟着常量走**：`src/tests/decision.test.js` 从调试句柄读 `CONSTANTS`，改数值不会让用例变红。改完照跑一遍确认没踩坏别的：

  ```bash
  node src/tests/decision.test.js
  ```

续播阶梯的总窗口 = `5×5s`（第一段）+ 重启 + `3×5s`（第二段）= **最长约 50 秒**。想让「多久才真正停下」变长/变短，优先改这两个次数，而不是把阶梯删掉。

### 3. 不要随手动的层

- **决策核心的判据**（任务点按 `jobid` 认、完成态看 `ans-job-finished`、可播只看 video/audio）——它们对应 [`0005`](../adr/0005-ppt-is-out-of-reach-so-confirm-past-it.md)/[`0006`](../adr/0006-task-point-is-identified-by-jobid.md)/[`0007`](../adr/0007-unplayable-task-points-are-skipped-too.md)，不是可调项；
- **`ADAPTER_FACTS` 里的选择器与文案**（`div.ans-attach-ct`、`iframe[src*="/ananas/modules/"]`、`/下一节/`、`/还有任务点未完成/` …）——站点改版时**只改这一处**，事实来源是 [`docs/sites/xuexitong.md`](../sites/xuexitong.md)；
- **`REASON_TEXT` / `PENDING_TEXT` 的文案**：措辞分两类（动手类说「N 秒后…」、放弃类说「再等 N 秒…」），时限一律由常量拼，别硬写数字。

## 三、日常使用

1. 打开学习页 `https://mooc1.xuexitong.com/mycourse/studentstudy?chapterId=…`，**不需要任何点击**，脚本自己开跑（`@run-at document-idle`）。
2. 右下角状态条是唯一的界面，位置固定、Shadow DOM 隔离，不影响站点样式。

### 状态条怎么读

```
正在运行　本卡片 0/1　|　本节点未完成 1（含 PPT）　|　430/1753s　|　还剩 1320s　|　5 秒后自动续播（第 2/5 次）
```

| 片段 | 含义 |
|---|---|
| `正在运行` / 停止原因 | 首段是当前状态；停下时这里换成「为什么停」 |
| `本卡片 x/y` | **当前卡片**里已完成/全部任务点（DOM 里只有活动卡片的内容） |
| `卡片 a/b` | 本节点共 b 张卡片、现在是第 a 张（只有一张卡片时不显示） |
| `后面还有 M 个任务点未完成（含 PPT）` / `本节点未完成 N（含 PPT）` | 平台自己在章节树上给的数，**含 PPT、不会归零**，只当参考。章节树拿得到时报「当前节点之后各节点之和」（`后面还有 M`），拿不到才退回「本节点未完成 N」 |
| `430/1753s` + `还剩 1320s` | 当前媒体的进度与剩余时长 |
| `N 秒后…` / `再等 N 秒…` | 倒计时，**只显示一条**。「`N 秒后…`」= 到点会动手（续播 / 推进）；「`再等 N 秒…`」= 到点会放弃（重启 / 停下）|

### 两个按钮

| 按钮 | 何时出现 | 做什么 |
|---|---|---|
| **停止** | 正在跑时 | 立刻终局，**不碰媒体**（不会替你暂停也不会替你恢复）；脚本不再自动续播，此后所有节点都停着等你 |
| **继续** | 停下之后 | 重置全部时间基准（重扫任务点、重找媒体）、按你的意愿直接起播一次，并继续驱动 |

> 「继续」是**人的动作**：脚本自己那次「重启」不会给你按钮——它用同一套口径重置记忆，但由脚本自己做，且**只做一次**。

## 四、脚本会做什么（自动行为）

- **依次播完本节点的可播任务点**：视频/音频直接 `play()`（实测该域已获 autoplay 授权，零点击可播，不需要先「打开」任务点、也不需要静音）。
- **找不到可播单元时按顺序找**：先在本卡片内定位 → 本卡片没有就切到还没找过的卡片（从第 1 张起）。
- **本节点确实没有能播的了 → 从章节树直接跳到「当前节点之后第一个未完成节点」**：只向前，中间那些已完成的节点一个都不访问（`0010`）。章节树拿不到时，才回退到老的「点下一节 + 替它确认确认框」那条路。
- **平台判定「完成」早于视频播完时，脚本不丢下它走人**：会继续把这一条播完再推进（实测平台可以在 89% 就判完成，那时还剩几十秒）。既不少看一截，也不会撞上「章节树还没刷新」的那几秒而误判（`0011`）。
- **脚本播不了的任务点一律跳过**：PPT（跨域，驱动不了）、判不出类型的模块、以及只有资料附件的节点。走章节树那条路时平台本来就不弹确认框；只有在回退路径上，脚本才会在**扫遍全节点确认没有可播单元**之后替你点确认框里的「下一节」（`0005`/`0007`/`0006`）。
- **媒体没在播时自动续播**：暂停 / 起播被拒 / 加载失败 → 每 5 秒再播一次，最多 5 次；用尽 → 重启一次脚本再试 3 次；再不行才停下并提示（`0009`）。成功判据是**连续在播满 5 秒**，不是「`paused === false`」。
- **不伪造观看**：从不改 `currentTime`、不碰 `multimedia/log` 的上报字段、确认框之外不替你点任何东西（`0002` 的边界）。停下就是停下，不会静默跳节。

## 五、停下之后怎么办（按停止原因查）

| 状态条文案（开头） | 原因 | 你要做的 |
|---|---|---|
| `你停止了脚本` | 你自己按了「停止」 | 点**继续** |
| `检测到多端登录风控警告…` | 同账号在别的设备/标签页也进了章节页 | 只留**一台设备、一个章节标签页**，关掉其余，刷新页面 |
| `这门课启用了人脸抓拍…` | `videoFaceCaptureEnc` 有值 | 脚本无法自动化，这门课只能手动 |
| `一直没找到可播的视频/音频元素，等了 30 秒…` | 任务点结构变了、或卡片层认不出来 | 检查页面是否正常渲染；必要时拉长 `UNREADY_TIMEOUT_MS` 或更新 `ADAPTER_FACTS` |
| `平台弹出了「还有任务点未完成」，但脚本还没把本节点的可播任务点找完/播完…` | 脚本的判断不可信（还没扫完） | 脚本**故意不替你确认**；看清楚再决定手动跳不跳 |
| `平台弹出「还有任务点未完成」，但脚本扫遍本节点却一个未完成任务点都没看到…` | 两边有一边错了 | 自己核对页面，别盲跳 |
| `视频/音频加载失败…（已自动续播 5 次、重启后 3 次均未成功）` | 资源真的坏了或网络持续不通 | 检查网络/资源，点**继续**重来一轮 |
| `窗口失去焦点后播放被暂停…` | 光标离开过窗口（平台的一次性 `mouseout`） | 正常情况脚本会自己救回来；出现这条说明 5+3 次都没顶住，点**继续** |
| `播放被暂停了…` | 同上（含**你自己在播放器上点的暂停**） | 点**继续**；**想真正暂停请按状态条的「停止」** |
| `播放卡住了（进度 20 秒不前进）…` | 缓冲/网络卡死 | 检查网络；这类**不走续播阶梯**，靠 `STALL_TIMEOUT_MS` 放宽 |
| `浏览器拒绝了自动播放…` | 该域还没有用户交互记录 | 在页面上先手动点一次播放，再点**继续** |
| `章节树说本节点还有未完成，脚本扫遍全部卡片却一个未完成任务点都没看到，又等了 15 秒复查仍是如此…` | 多半是站点改版把任务点容器换掉了（脚本漏判），它不敢替你跳 | **别盲跳**；先核对这个节点页面上到底有没有没做的东西，再手动处置 |
| `当前节点之后没有带未完成计数的节点了，脚本结束…` | 课程到头了；也可能是章节树没渲染全、或后面只剩脚本播不了的任务点 | 到头就收工；觉得还有内容就刷新页面再看一眼 |

## 六、硬约束与注意（踩过坑的）

- ⚠️ **只开一个章节标签页、只登一台设备**：同一账号第二处进入章节页会被判异常学习并**登出其中一个会话**；**同一个浏览器里另开一个章节标签页也算**。
- ⚠️ **「停下一次就停到底」**：换节是**局部刷新**，脚本实例跨节点存活——在某个节点停下后，往后的节点它都不管，除非你点**继续**。
- ⚠️ **你在播放器上自己点的暂停也会被自动续播**：平台按一次性 `mouseout` 判「离开窗口」，脚本按 `document.hasFocus()` 判，两档分不开（`0009` 如实记的代价）。逃生口只有状态条的**停止**。
- **PPT 任务点脚本处理不了**：承载 PPT 的查看器在跨域域（`pan-yz.chaoxing.com`），父页面读不到也驱动不了它的滚动（[`0004`](../adr/0004-ppt-must-be-scrolled-to-the-end.md)、[`0005`](../adr/0005-ppt-is-out-of-reach-so-confirm-past-it.md)）——硬约束，别再指望「让脚本滚 PPT」。脚本的做法是**跳过它**——走章节树那条路时平台根本不弹确认框，只有在回退路径上才代为确认。
- **`本节点未完成 N（含 PPT）` 不会归零**：只要节点里有 PPT，这个数就一直 > 0，不代表脚本卡住了。
- **播放完到翻节之间有 15 秒固定延迟**（`ADVANCE_DELAY_MS`）；真机上这一支**只在本卡片最后一个可播任务点播完时才走到**——本卡片还有别的未完成任务点时，上一个一播完脚本当场就选中并起播下一个（`findMedia()` 给「已播完」的元素 +2 分，`src` 里已注明）。
- **探到平台风控 / 人脸抓拍立即停**：这两类脚本不处理，交给人。

## 七、排查：状态条不出现

按顺序看：

1. **`@match` 对不对**——只能在 `mooc1.xuexitong.com/mycourse/*` 下注入；
2. **Tampermonkey 里脚本是启用状态**吗，站点有没有被加进「排除」；
3. 用第一节那条 `typeof …AUTO_RESUME` 确认代码真的跑起来了（控制台能读到句柄 = 注入成功但可能 `isStudyPage()` 判否）；
4. **刷新一次学习页**：脚本只在文档加载时注入一次；若你是从别的页面用页面内跳转（`pushState`）进到学习页的，Tampermonkey 不会补注入，刷新即恢复；
5. 状态条固定右下角、`z-index` 拉满，若被别的东西挡住会看不见——但仍会正常跑。

脚本在真机上「跑不动」时，先跑用例看决策核心有没有坏：

```bash
node src/tests/decision.test.js        # 全部（当前 94 条）
node src/tests/decision.test.js 续播    # 只跑名字含「续播」的
```

## 八、进阶
