# 暂停后自动续播：两段阶梯（5 次 → 重启一次 → 3 次）

[`0002`](./0002-no-skip-or-fake-watching.md) 的 Considered Options 里有一条被明确否掉的方案：**失焦暂停后静默自动续播**，理由写在那条 ADR 的正文里——「那等于人不在时也产生观看时长」，与「直接确认跳过未完成的任务点」并列。这一条现在被反转。

起因是一条**实现事实**加一条**用户判断**：

- 播放器的暂停是 videojs 的 `studyControl` 插件做的：监听绑在**播放器元素**上的 `mouseout`，且 `relatedTarget` 为空（光标真的离开窗口）才暂停。**一次性事件、不轮询**；光标回到窗口只置一个标志位，**平台自己不恢复播放**（见 `docs/sites/xuexitong.md`）。也就是说，**脚本 `play()` 一次就能顶住**，此后不会再被暂停。
- 用户判断这个暂停**不是平台的需求**：项目本身不要求「离开就暂停」，是前端开发人员失误加进来的；本脚本是**临时处理方案**。`docs/sites` 里平台自陈的完成条件文案（「观看时不可离开或将页面最小化」）作为原始证据**保留**，但不再作为脚本的行为依据。

于是我们决定：**暂停之后、或脚本自己判定的「起播被拒 / 媒体加载失败」之后，不再直接停下，而是自动续播**，形状是两段阶梯：

- **第一段**：每 `RESUME_INTERVAL_MS`（5 秒）对当前媒体再按一次播放，最多 `RESUME_MAX_ATTEMPTS`（5）次；
- 第一段用尽 → **重启一次脚本**（重置全部时间基准、重新扫任务点、重新找媒体、再播一次）；
- **第二段**：重启后再试 `RESTART_MAX_ATTEMPTS`（3）次，间隔仍是 5 秒；
- 第二段用尽 → 才**真正停下**，沿用原来的停止原因，文案加后缀「已自动续播 5 次、重启后 3 次均未成功」；此后只能由人点「继续」（「继续」会把「已经重启过」这件事一起重置，于是又是完整的一轮）。

适用范围只有四档：`focusLostPause`、`manualPause`、`playbackRefused`、`mediaLoadFailed`。**用户按「停止」永不自动续播**（`0008` 不受影响）。

## Considered Options

- **无限的静默续播**：放弃。它等于取消「停下」这个概念——出现持续性的坏状态（站点改版、媒体真坏）时脚本会一直徒劳地按播放，用户永远看不到「它不行了」。
- **只覆盖暂停类，不加重启**：放弃。暂停类常见的两种失手是「元素被换掉」「页面状态乱了」，只有重置记忆、重新扫一遍才救得回来；而且重启是用户明确要的。
- **`stalled` 与 `mediaNotFound` 也进阶梯**：放弃。它们接进来是**空操作**——前者媒体 `paused === false`（在播、只是卡在缓冲），对没暂停的元素调 `play()` 什么也不会发生；后者那一刻根本没有媒体元素可播，而且它本来就在每 4 秒重试定位。两者都只会把停止推迟 25 秒。
- **直接关掉播放器那个暂停开关**：事实层面就走不通。插件选项 `enableSwitchWindow` 的值在**构造时读进闭包**，事后改不动（见 `docs/sites`）。
- **给「续播也用尽」新增一条停止原因**：放弃。沿用原来的原因 + 后缀，才能保住「为什么停」这个信息（失焦 / 手动 / 被拒 / 加载失败）；只为这件事新增一条原因，还会连带逼着补一条用例。

## Consequences

- **如实接受的代价**：脚本会在**无人观看**时继续让播放前进，平台按已看时长照常上报。这正是 `0002` 当初否掉这条方案的理由，现在由用户拍板接受——与用户此前说的「这个项目不怕留下跳过痕迹」属同一类自我约束的放松。
- **第二处反转**：spec 的 Implementation Decisions 写着「`play()` 被拒时归入停下并提示，**不重试**、不静音重试」。现在首次起播请求之外，最多再重试 8 次（5 + 重启后 3）。
- **最长窗口 50 秒**：从「发现异常」到「真正停下」最多 50 秒（5×5 + 重启 + 3×5）。对暂停类无所谓（通常第 1 次就活过来）；对**原先立刻停**的「媒体加载失败」是反馈延迟从 0 变成 50 秒，换来网络抖动时能自己救回。
- **你在播放器上自己点的暂停也会被自动续播**：脚本判「失焦」用的是 `document.hasFocus()`、平台用一次性 `mouseout`，两者错位——光标离开窗口但窗口仍有焦点时会被判成 `manualPause`，而「光标离开窗口」那一档必须走这条路，两档分不开。逃生口只有状态条上的「停止」。
- **「停止」的含义变了**：从「立刻终局」变成「自动续播用尽之后才终局」。`STOP` 仍是唯一的终局，「继续」仍是唯一的解铃人；重启由脚本自己做，但**只做一次**。
- **退休**：`PAUSE_GRACE_MS` / `START_GIVEUP_MS` 两个常量、`PENDING.PAUSED` / `PENDING.START_GIVEUP` 两条等待（连文案一起删）。起播类的**首次**请求仍在发现时立刻发出，阶梯的第一次尝试统一在 5 秒后——全脚本只有一套时钟。
- **成功判据是「连续在播满一个间隔（5 秒）」**，不是「`paused === false`」：平台的播放器之间有一个 1 秒轮询的「同一时刻只有一个能播」守卫（见 `docs/sites`），「起了又被按停」会被瞬时判据当成成功，从而把 5 次上限悄悄变成无限。
- **适配层不加新接口**：续播用的就是「继续」按钮那一个动作（对当前媒体按一次播放），新增的只有决策核心的动作枚举与记忆字段。
