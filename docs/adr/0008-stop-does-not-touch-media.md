# 「停止」只撤出脚本，不碰媒体

状态条上的「停止」让脚本**撤出驱动**：清掉定时器、把判定停在 `userStopped`，**不暂停也不改动页面里的媒体**——那一刻还在播的视频继续播，脚本也不再接管它（要恢复只能点「继续」，而「继续」会重新替当前媒体起播一次）。考虑过「停止时顺手 `pause()` 那个脚本自己起播过的媒体」（启动记忆里就有 `startRequestedKey`，判据现成），放弃它，是因为脚本该撤回的只有「驱动」这一件事：媒体播不播归人和平台管，而「停止 / 继续」一旦会开关媒体，这两个按钮就从「脚本的开关」变成了「页面的开关」——与 `0002`「不代用户做决定」的边界就不是差一步，而是越过去了。

## Considered Options

- **停止时 `pause()` 脚本自己起播过的那一个媒体**：边界上说得通（只撤回自己造成的动作，而且平台的上报是按已看时长增量的，暂停不会留下假观看）。放弃它的理由见上：给「停止」加上副作用，等于把按钮的语义放大成「媒体开关」；真想停住视频的人直接点播放器上的暂停键，那本来就是他的地盘。
- **停止时 `pause()` 当前正在播的媒体（不管谁起播的）**：实现最简单。放弃它，是因为脚本没有可靠判据区分「谁起播的」，它会连用户自己点开的播放一起按停——语义越界的按钮会在最不希望的时候生效。

## Consequences

- **停止之后媒体继续播，平台侧会继续按已看时长上报**（模块自己在上报，与脚本无关）。如实接受：用户按「停止」通常是想让脚本别管了，而不是想让视频停下来。
- 「停止 → 继续」在媒体上的表现是**不对称**的（不动 → 起播一次）：`controller.resume()` 会重置全部时间基准并调 `adapter.playOnce()`。这是刻意的，不是疏漏。
- 这条与 `0002` 的关系是**同一侧的**：不替用户点确认框、不静默续播、也不替用户按暂停——脚本只做平台不会替它做的那件事（挑下一个可播单元并起播）。
