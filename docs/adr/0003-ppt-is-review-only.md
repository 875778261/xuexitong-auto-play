# PPT 任务点不计入需完成范围，可在其为唯一未完成项时代为确认推进

目标站点的任务点分「视频 / PPT / 音频」三类，其中 **PPT 只作复习用途**：它不产生观看时长，也不进入「观看时长 ≥ 总时长 90%」这条判定。因此我们决定：PPT 任务点**不计入需完成范围**，当节点内未完成的任务点**只剩 PPT** 时，脚本可以代为点击确认框里的「下一节」。

这是对 `0002`（不代为确认未完成任务点的确认框）的**收窄**，不是推翻。`0002` 要守住的是"不让脚本替平台以为你在看"；跳过 PPT 不产生任何观看时长、不改变任何上报字段，落在该边界之外。`0002` 的「停在那里并提示」应读作：**仅在媒体（视频/音频）任务点未完成时**停下并提示。

## Considered Options

- **严格遵守 `0002`，任何确认框都停下提示**：边界最clean，但「自动跑完整门课」会在每个纯 PPT 节点断一次，用户得守着。放弃它，是因为断点的性质与 `0002` 防的事不同类。
- **把 PPT 也自动播完**：不必碰确认框，且"完成"语义更整齐。放弃它，是因为 PPT 的完成判定与交互方式完全未探查，把 v1 的范围从"已实测的一条路径"扩张成"两条都要重新探"。

## Consequences

- 脚本必须能区分**确认框**与其它弹窗/遮罩，并且只在「未完成项皆为 PPT」时替用户点「下一节」。误判的最坏后果是推进而非伪造观看——危害有界，但仍需在实现时当场确认确认框的真实结构与按钮文案。
- 混合节点（既有未完成视频、又有 PPT）不适用本 ADR：先按正常流程播完媒体任务点，之后只剩 PPT，再走本 ADR。
- 平台是否把"仅剩 PPT"同样计入未完成、点「下一节」是否真的弹框，属于**可查证的事实**，留到实现时用探查会话当场确认；spec 按"会弹框"写默认实现。
- 由此，`0002` 的适用范围被明确为媒体任务点；两份 ADR 需一起读。
