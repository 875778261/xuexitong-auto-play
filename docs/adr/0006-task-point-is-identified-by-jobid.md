# 任务点的判据是 jobid，不是容器外形；只剩资料附件的节点直接推进

`.ans-attach-ct` 这个「任务点容器」是上一轮从 PPT 卡反推出来的。实测发现平台把**资料附件**也渲染进同样的容器里：模块是 `/ananas/modules/downloadfile/index-pc.html`，iframe 上明写 `module="downloadfile"`，**没有 `jobid`**（属性上没有、`data` JSON 里也没有），没有 `ans-job-icon`，而且平台根本不把它当回事——不计入 `jobUnfinishCount`，也不为它拦住「下一节」（`PCount.next` 里 `checkJob()` 为假）。实测的两处：节点「1.1 音标教学PPT」只有一个容器，里面是 `音标.ppt`；节点「2.1.2 《……够了》系列电子书」有两个容器，是两份 `.pdf`。同课的「2.1.1 词根词缀背单词」与「2.2 提升四级听力的技巧」连容器都没有。

因此我们决定：**任务点的唯一判据是 `jobid`**——模块 iframe 的属性上有，或者 `data` JSON 里有（PPT 的只写在 `data` 里）。两处都读不到，就**不是任务点**。于是「一个节点里只剩资料附件」与「一个节点里什么都没有」等价：本卡片没有任务点时，先按一个短窗口期当作渲染延迟，过了就照**卡片账本**办——没扫遍本节点的其他卡片就去扫，扫遍了就推进到下一个节点。

**「本卡片一个任务点都没有」不再等于「采不到任务点，只好停下」**，也不再参考平台自己的 `input.jobUnfinishCount`：平台说有未完成而脚本采不到时，照样推进，不停。

这条不动 `0002`：资料附件不是任务点，推进时平台也不弹确认框，所以没有任何「代为确认」的新授权。

## Considered Options

- **按模块类型判，认不出就停下**（`0005` 的 Consequences 里写的那条）：放弃它，是因为判据找错了位置。资料附件长得像任务点，是因为它**共用容器**，不是因为它「是个陌生类型的任务点」；按类型判会把「这个节点没什么可做的」误报成「我不认识它」——实测状态条就是这么报的：`有个未完成任务点的模块类型认不出来…　本卡片 0/1`，那个 `1` 是一份 `.ppt` 附件。
- **保留「卡片全空就停下让人看」**（包括平台说有未完成时）：最保守。放弃它，是因为这类节点在课程里**成串出现**（`1.1`、`2.1.1`、`2.1.2`、`2.2`），而「下一节」是**局部刷新、脚本实例跨节点存活**（见 `docs/sites`）——停一次不是断一次，是从这里往后都不再推进。
- **用 `input.jobUnfinishCount` 做交叉校验**（平台说 > 0 而脚本采不到就停下）：放弃它的前提是「平台那张确认框已经在做同一件事」，见下面第一条 Consequences。⚠️ **前提已被 [`0010`](./0010-jump-to-next-unfinished-node.md) 拿掉**（树跳转不经过确认框），这条交叉校验因此被重新捡回来。

## Consequences

- **删掉停止原因 `taskPointsNotFound`**（原来「连续 30 秒采不到任务点就停」）。它守的位置已被「本卡片 0 任务点 → 推进」接管，留着就永远不会触发——`src/tests/decision.test.js` 末尾的自检会逼你表态。
- ~~**`unknownTaskPointKind` 保留为兜底停下**~~（从「资料附件也触发」收窄成只对带 `jobid` 的真任务点生效）。⚠️ **这一条已被 [`0007`](./0007-unplayable-task-points-are-skipped-too.md) 取代**：认不出类型的真任务点同样属于「脚本播不了的任务点」，一律跳过并代为确认；这条停止原因已删除。
- **安全网不是脚本自己造的判据，而是平台那张确认框**：真还有没做的，`PCount.next` 不会跳、而是弹「还有任务点未完成」。脚本看到确认框却一个未完成都没看见时，停在 `dialogWithoutUnfinished`（「两边必有一边错了」）。⚠️ **因此「确认框的判定」必须排在「本卡片空就推进」之前**——否则那条提前返回的路径会让人永远看不到弹层，安全网失效。⚠️ **这一条已被 [`0010`](./0010-jump-to-next-unfinished-node.md) 改写**：推进改成从章节树直接跳节点之后，`PCount.next` 那条路只在**章节树不可用**时才走，安全网改由**树上的计数**承担（新停止原因 `treeUnfinishedNotFound`）；确认框那一支降级为回退路径专用。
- `input.jobUnfinishCount` **只用来显示进度，不参与决策**。⚠️ **这一句已被 [`0010`](./0010-jump-to-next-unfinished-node.md) 推翻**：它现在正是「选下一个要跳过去的节点」的判据。
- 已知代价（如实记）：连续两个「空卡片节点」之间任务点签名相同（都是空签名），「页面没变化时不重复点下一节」的 8 秒冷却会额外生效一次，每个空节点多等约 8 秒。
- 另一个如实记的代价：适配层一旦漏判（站点改版换了容器类名、或某个真任务点漏了 `jobid`），脚本会把真任务点也当成资料附件忽略掉，表现为**静默推进**。这件事只在推进那一刻由平台的确认框兜住，脚本自己不另做判断。
