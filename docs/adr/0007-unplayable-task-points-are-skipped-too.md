# 认不出类型的任务点也跳过：`0002` 的例外从「PPT」扩成「脚本播不了的任务点」

`0005` 开的例外是「本节点**只剩 PPT** 未完成时，推进并代为确认」，理由是「脚本在技术上够不到它」。`0006` 之后任务点先按 `jobid` 认，于是还剩最后一种未完成：**模块类型认不出来**。它是**真任务点**——平台把它计入进度、也会为它拦住「下一节」——但脚本同样播不了它。它和 PPT 是同一性质：**脚本做不到，而且停下也没有更好的出路**。

因此我们决定：**脚本播不了的任务点一律跳过**。扫遍本节点全部卡片、确认再没有可播单元之后推进；平台弹「还有任务点未完成」时代为确认。`0002` 的例外从「只剩 PPT」扩成「只剩**脚本播不了**的任务点」，例外之外的部分（`0002` 的正文、以及 `mediaIncompleteConfirm` / `dialogWithoutUnfinished` 这两条「脚本判断出错」的停止）都不动。

这条**取代**了 `0006` 里写的「`unknownTaskPointKind` 保留为兜底停下」。

## Considered Options

- **维持停下**（`0006` 原本的写法）：守住「不认识的东西就别碰」这条边界。放弃它，是因为停下换不来任何东西——用户不会因为这个提示去手工完成一个连脚本都不认识的模块；而每遇到一次，整条自动流程就断在那里。而且「下一节」是**局部刷新、脚本实例跨节点存活**（见 `docs/sites`），**断一次就是断到底**。
- **只推进、不代为确认**：边界更干净。实际做不到——它是平台计入进度的真任务点，`PCount.next` 里 `checkJob()` 为真，不点确认根本不跳转，等于没改。要么连带授权一起给，要么维持停下。

## Consequences

- 停止原因 **`unknownTaskPointKind` 删除**（连同它的用例与状态条文案）。`src/tests/decision.test.js` 末尾的自检要求每条停止原因都有用例，所以它不可能只删一半。
- **代价如实记**：脚本会跳过一个它不认识的任务点，这个节点在平台上仍然显示未完成——与 PPT 的代价同款。用户明确选择了「宁可跳过，也不要断」。
- 「脚本播不了的」这一类**不需要逐个类型列举**，定义就是 `!isPlayableUnfinished(t)`：kind 不是 `video` / `audio` 的一切未完成任务点。以后平台再加内置类型时，只需要决定要不要把它加进 `moduleKindMap`（＝「能播的集合」），不必改这条判断。
- 确认框那一支的行为不变：只有**扫遍全部卡片、没有可播单元、且账本里确实见过未完成任务点**时才代为确认。「一个未完成都没看到，平台却弹了确认框」仍然停在 `dialogWithoutUnfinished`。
- ⚠️ 连带影响：脚本现在**没有任何**一条停止原因与「任务点类型」有关。剩下的停止只有三类——用户/平台叫停（`userStopped` / `loginRiskControl` / `faceCaptureCourse`）、媒体出问题（`mediaNotFound` / `mediaLoadFailed` / `stalled` / `playbackRefused` / 两条暂停）、以及「脚本判断与平台判断对不上」（`mediaIncompleteConfirm` / `dialogWithoutUnfinished` / `courseCompleted`）。
